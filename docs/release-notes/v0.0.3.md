# cpuv 0.0.3

This Windows release adds MINGW64 binary packages, GCC toolchain management, and direct access to Conan remotes and recipes.

- Compatible x86-64 POSIX/SEH MSYS2 compilers select UCRT64 for UCRT or MINGW64 for MSVCRT. Package ownership and linking use the selected provider namespace.
- cpuv toolchain list discovers installed compilers. toolchain install uses an existing discovered MSYS2 pacman host, supports --dry-run and offline reuse, and verifies the resulting compiler. No drive or username is assumed.
- toolchain use verifies and selects a compiler in per-user storage; reset restores ordinary discovery. Windows PATH and existing project pins are preserved. --compiler and compiler environment variables take precedence.
- cpuv conan exposes upstream remote, export, create, profile, cache, and other native commands using the same compiler/profile home as dependency synchronization. Standalone Conan embeds Python.
- Full name/version@user/channel references, optionally with a recipe revision, select Conan automatically. Dependency tables can also declare a reference. No package-specific library recipes or aliases are added.
- Direct opposing-runtime imports are rejected, and nested library archives in Conan deployments are inspected. Older prepared MSYS2 metadata is regenerated for the namespace-aware link model.
- Archive signatures distinguish text .LIB documents from actual libraries. Licenses remain packaged; malformed archives in library directories and wrong-architecture COFF members still fail validation.
- Conan uses separate target and native build profiles. Verified CMake/Ninja versions are declared as platform tool requirements, allowing 32-bit target libraries to build with native x64 tools. --build-compiler/CPUV_BUILD_CXX selects a native GCC independently when required.

Use an existing MSYS2 host for compiler installation; cpuv does not bootstrap MSYS2 itself. Package availability and supported compiler features remain upstream requirements. Nix/WSL and Linux packages are outside this native Windows release. Recipes run with your permissions. Local/private recipes must be distributed separately from the lockfile, and changing the compiler/profile can require reconfiguring its provider home.

The native installer, portable ZIP, bootstrap, and checksum assets remain available through the standard packaging workflow. See [Windows providers and toolchains](https://github.com/Bongusrihas/cpuv/blob/v0.0.3/docs/windows-providers.md), [compatibility](https://github.com/Bongusrihas/cpuv/blob/v0.0.3/docs/compatibility.md), and [security](https://github.com/Bongusrihas/cpuv/blob/v0.0.3/SECURITY.md).

Local verification passed warning-free workspace Clippy and a locked release build. Eight Windows workflow checks covered real MINGW64 package installation/linking, compiler selection, native Conan remote commands, exported recipe creation, full-reference offline installation, consumer execution, lock/cache reuse, failure preservation, and removal. Five binary checks accepted matching UCRT/MSVCRT DLLs, rejected both opposing-runtime combinations, and rejected an incorrect architecture. Development fixtures and verification reports remain outside the source distribution.

Maintenance verification additionally installed the repository's OpenBLAS package, preserved its .LIB license, linked and executed a dot-product consumer, and reused the environment offline. Generic text/archive fixtures retained corruption and architecture checks. A real 32-bit GCC 16.2 build created and installed a CMake/Ninja-backed library offline with x64 platform tools and executed its PE32 consumer. ConanCenter graph resolution for GCC 6, x86, gnu14 accepted fmt/12.2.0, openblas/0.3.30, and eigen/5.0.1, using the supplied CMake as a platform requirement. This graph check did not compile those packages with GCC 6.3; support for that compiler remains an upstream constraint.
