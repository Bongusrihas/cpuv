# cpuv 0.0.1

The first public release of cpuv: a C++ dependency and compile-and-run workflow for Windows GCC.

## Install

Download **cpuv-setup.exe** and run it, or paste this into PowerShell:

```powershell
irm https://github.com/Bongusrihas/cpuv/releases/latest/download/install.ps1 | iex
```

The prebuilt application requires no Rust, Cargo, Git, or separate Visual C++ runtime installation. A working native GCC toolchain is required to compile C++ programs. The portable ZIP supports offline installation through install.cmd.

## Included

- Native Windows installer, user PATH registration, portable distribution, and verified self updates.
- Automatic GCC discovery, including discovered MSYS2 installations without a fixed installation path.
- Compatible MSYS2 UCRT64 binary packages and recipe-backed source builds using the selected GCC/profile.
- Embedded fmt, Eigen, and zlib source recipes, custom registries, and pinned CMake/Ninja bootstrap.
- Parallel downloads, SHA-256 verification, offline cache reuse, and hardlink-based project environments.
- Exact repository package names, similar-name suggestions, and linking through package-owned metadata.
- Managed compilation and execution with generated EXE, DLL, and intermediate files under the hidden .cpuv directory.
- Configurable archive limits: 16 GiB downloaded and 64 GiB expanded per archive by default. Index metadata has a separate configurable limit.
- A doctor command that compiles, links, and runs a program with the selected toolchain.

## Compatibility

The prebuilt application targets Windows 10 or newer on x64. The supported binary provider is MSYS2 UCRT64. Other recognized native GNU GCC profiles use source recipes; every additional source dependency needs a recipe and compatible compiler features. Arbitrary linkers, MSVC/Clang interoperability, universal ABI compatibility, and sandboxed builds are outside this release.

Use exact MSYS2 package names such as eigen3 and lapacke. No library-specific aliases, automatic sibling packages, include directories, or linker-module defaults are built into the resolver. Ambiguous link interfaces require explicit project configuration. Existing locks that relied on older aliases may need regeneration.

## Validation

Formatting, Clippy, and release compilation passed locally. Functional checks covered UCRT and MSVCRT source builds, a nondefault libstdc++ ABI profile, metadata-driven binary linking, offline cache reuse, native/portable installation without Rust, and streamed downloads and ZIP64 extraction of 2 GiB plus one byte. These checks are evidence for those cases, not a universal compatibility guarantee.
