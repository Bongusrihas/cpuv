# cpuv 0.0.4

This Windows x64 release stabilizes dependency installation, metadata linking and environment recovery, and adds compiler/provider integration behind explicit compatibility boundaries.

- Preserve linker operand order, static dependency ordering, scoped whole-archive/group flags, private static interfaces and multi-flag pkg-config variables. Metadata paths containing spaces remain single operands; uppercase `.PC` and DLL extensions are handled consistently.
- Preserve compiler stdout outputs and response-file quoting, reject colliding object names before compilation, and deploy runtime DLLs through the standalone compiler shim.
- Verify complete environment inventories, compiler/SDK contents and project requests. Journal environment/manifest/lock updates, hold reader leases for subprocess lifetimes, and recover interrupted updates without discarding recovery data.
- Quarantine damaged package/blob cache content and restore verified archives, including offline with a complete cache. Serialize publication/repair and handle filesystems without hardlinks.
- Keep `sync` frozen to the selected request/profile; use `lock` for intentional resolution. Verify requested Conan linkage against resolved settings and artifacts. Discover custom Cargo target directories for developer installation.
- Add named profiles, Release/Debug configuration, MSVC and GNU-style Clang adapters, Conan options/shared/static selection, native CMake/Ninja/CTest integration, pinned vcpkg MSVC integration, `plan`, `verify`, and application runtime bundles.
- Retain behavioral tests and complete Windows acceptance gates in CI and release workflows, with logs, compiler identity and source/binary checksums.

## Validation and limits

The Phase 1 gate exercises 37 unit/regression tests, one native local-repository acceptance test, an isolated custom-target installer and real Conan shared/static/frozen/offline/repair consumers. Transaction recovery includes 32 actual process-exit scenarios. Run `scripts/test-phase1.ps1 -ReleaseBuild -Compiler PATH_TO_UCRT64_GXX` to repeat release acceptance. CI retains its evidence artifacts.

The main acceptance lane is Windows x64 with UCRT64 GCC 16.2.0. Native MSVC 19.51, GNU-style Clang 22.1.8, and vcpkg zlib/CMake consumers were also exercised during implementation. Those individual checks do not certify every library or toolchain version. clang-cl, additional architectures, older/current compiler matrices and clean-machine coverage remain incomplete. vcpkg offline mode verifies intact installations; offline rebuilding a missing vcpkg tree is not implemented. Runtime bundles exclude unsupported delay imports and are not complete offline development bundles.

The engine contains no library-specific recipes, aliases, patches or fix branches. Library names in tests/examples are fixtures; package interfaces and build instructions remain provider-owned. Bootstrap versions/checksums and the configurable vcpkg revision are intentional reproducibility pins.

Use [compatibility](../compatibility.md), [catalog installation](../source-builds.md), [Windows providers](../windows-providers.md) and [release instructions](../releases.md) for operational details. Conan recipes and upstream builds run with the user's permissions; package signatures and hermetic execution are not provided. Universal library/compiler compatibility is not claimed.
