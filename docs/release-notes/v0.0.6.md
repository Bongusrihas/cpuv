# cpuv 0.0.6

This maintenance release fixes dependency editing, native build configuration, runtime environments, and cache consistency identified in the codebase review.

## Behavior changes

- Repeated `add` preserves detailed dependency options, linkage, and private references. Updating a private recipe requires a full recipe reference; replacing a source declaration remains explicit.
- CMake builds prepare all declared tools, including interpreter launchers. Native tests receive declared runtime search paths. Generic `run` commands receive the selected developer environment.
- C++03 maps to CMake's C++98 category; ISO/GNU extensions are explicit and unsupported standards fail. Returning to `default` clears CPUV's cached standard options.
- Compiler/configuration overrides through build variables or raw arguments are rejected; select a matching profile instead.
- Explicit provider choices survive profile creation. vcpkg profiles validate their final compiler/provider combination.

## Lock and cache migration

Conan locks now record compiler/SDK/bootstrap input identity and selected host/build recipe/package revisions, settings, and options. Run `cpuv lock` once to migrate older catalog locks before rebuilding through the provider. Existing verified deployed snapshots remain available for offline restoration with matching inputs. A frozen provider sync rejects binary graph drift instead of silently accepting another revision.

Artifact keys use canonical provider-lock identities. Verified older snapshots are discovered by installed resolution/request/compiler identity; provider payload formatting no longer causes an offline cache miss.

Offline import takes the exclusive cache lease, preventing readers from observing partially copied shared cache objects. vcpkg checkout/bootstrap uses a per-revision lock shared by search and installation.

## Performance

Unchanged Make/MSBuild copied inputs retain their timestamps. DLL deployment uses bounded PE mappings, streaming content comparison, and an indexed search. pkg-config parsing reuses its Requires expression and a deterministic topological ready queue. Bootstrap writes are asynchronous; cache inspection can coexist with cache readers. These changes remove redundant work without claiming a universal speedup.

## Scope

Windows remains the shipping platform. Workspaces, remote caches, additional platforms, and larger product features remain in the roadmap. Recipe execution is not sandboxed, and source rebuilds are not a promise of bit-identical outputs.

Validation results are recorded in `improvements.md` after the release checks complete. GitHub release automation runs the native acceptance gates before publishing assets.
