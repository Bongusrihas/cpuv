# cpuv 0.0.2

This release adds application uninstall, a shorter dependency removal command, and automatic ConanCenter fallback when MSYS2 cannot supply the requested environment.

## Install, update, and remove

Download cpuv-setup.exe for native per-user installation, or extract the portable Windows ZIP. Prebuilt assets require no Rust, Cargo, system Python, or administrator access. Existing users can run:

```console
cpuv self update
```

Remove a project dependency with cpuv rm PACKAGE; cpuv remove remains available. The remaining graph is synchronized, preserving dependencies still needed by other roots and shared caches.

Remove the application with cpuv uninstall. Use cpuv uninstall --dry-run to preview affected executables, recognized helpers, and user PATH entries. Shared tool directories, other binaries, project source, .cpuv environments, GCC, and dependency caches are preserved. Custom portable invocations affect that installation only.

## Dependency installation

- Missing MSYS2 packages now select ConanCenter for the whole environment; --catalog selects it explicitly. Provider graphs are kept separate.
- cpuv-owned library recipes, patches, custom recipe registries, recipes.toml, and --recipes have been removed. build-tools.toml pins bootstrap tools only.
- The generic adapter bootstraps standalone Conan/CMake/Ninja, resolves transitive requirements, reuses compatible packages, and builds missing binaries with the selected native MinGW GCC.
- Public pkg-config interfaces, saved compiler profiles, upstream revision locks, provider cache-integrity checks, offline binary-cache reuse, and staged deployment support this path.
- Missing-package suggestions no longer return unrelated one-letter substring matches.

Packages must exist in the selected catalog and support the compiler/platform. Catalog names can differ from MSYS2 names; use the exact upstream name. Arbitrary GCC/linker/ABI combinations and unregistered archives are not universally supported. Conan recipes execute upstream code; cpuv's MSYS2/bootstrap transfer limits do not govern recipe downloads.

## Documentation and verification

README, architecture, compatibility, security, and release documentation describe the final behavior. The project encyclopedia includes a dated source audit and a separate application uninstall implementation update; its original hashes and counts remain historical snapshots.

Local validation passed formatting, warning-free workspace Clippy, and a locked release build. External verification covered six dependency-removal scenarios and eight application-uninstall checks, including native executable deletion, PATH preservation, and rollback failures. Development fixtures, test suites, and generated verification reports remain outside the source distribution.
